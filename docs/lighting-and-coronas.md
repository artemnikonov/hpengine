# Lighting, lightmaps, mover lightmaps and coronas

The original lights the world in three separate places: surface lightmaps (`FLightManager::SetupForSurf`, rebuilt per frame when a light can change), per-actor vertex lighting (`FLightManager::SetupForActor`, inside `DrawFrame` for every mesh), and light coronas (a block at the tail of `URender::DrawFrame`). All three live in Render.dll 1.53. HPEngine ports their decisions into Core; the frontend only runs the per-vertex or per-texel work it is handed.

## Surface lightmaps (`SetupForSurf`, slot 3)

- Baked shadows and static light live in the level's lightmaps (`LightBits`, one shadow mask per light of a surface). At draw time `SetupForSurf` (the level branch is `FUN_10b077f0`) builds the texture: a zone ambient seed, then each light in list order.
- Selection: for a level surface the light list is `FLightMapIndex.iLightActors` in `Model->Lights`, null-terminated. Every element goes through the categoriser (`FUN_10b097b0`). The mask pointer of an accepted element advances by `k * VClamp * ((UClamp + 7) >> 3)` where k is the index in the list, counting rejected entries too (0x10b07cb6..0x10b07cbc). There is no `bSpecialLit` selection in this branch; bit 0 of +0x1f0 is read only in the mover branch (0x10b07b08, 0x10b07b38) and for `bDarkLight` (0x10b03632).
- Then the draw record's +0x48 list is appended: `URender::SurfLights`, the frame's dynamic lights (see below), with no mask.
- Categories: 0 is a bStatic light of LightType 1 with an effect that is neither spatially dynamic nor changing-shadow (effect tables at 0x10b38114 and 0x10b38118); 1 is another bStatic/bNoDelete light without `bDynamicLight`; 2 is the rest; 3 is LightEffect 15, which never reaches a lightmap. With `UClient.NoDynamicLights` set, 1 becomes 0 and 2 is rejected.
- Caches: key 0x18 holds the ambient seed plus the category-0 lights (built once per lightmap and zone); a per-frame result (key 0x31) is rebuilt only when the viewport frame number changes and categories 1 or 2 exist. Category 1 has two caches: flag 0x84 non-zero keeps an expanded mask (key 0x15) and runs the filler every frame; zero keeps the filler output (key 0x16), run only on a miss. The merge runs every frame.
- Because the 0x31 result is keyed by the viewport frame, the first frame in `DrawFrame` order (children before the parent) that draws a surface builds it and the others reuse it.
- Colour: `FGetHSV(Hue, Sat, 255)` times `Level.Brightness` times the brightness type function (the table at 0x10b38288 by LightType, applied before the [0,1] clamp). Fillers include radial, `SlowWave` (0x10b04388) and `Interference` (0x10b043cd), which read LightPeriod and LightPhase and the global random tables (`FGlobalRandoms`) as they stand after this frame's `PreRender`. Channels saturate at 127; `bDarkLight` subtracts with borrow and floors at 0 (0x10b0365f..0x10b03689). An absent shadow mask is filled with 0x7f (`FUN_10b02970`).
- Precision: slot 3 runs in the x87 24-bit window. The radial sampling was measured at both precisions on the same cases with identical results; the frame effects are ported at float precision.
- Port: [`HP1.Core/Runtime/VM/SurfLightmap.cs`](../HP1.Core/Runtime/VM/SurfLightmap.cs) (the fill, one owner for the level bake and the mover rebuild), [`HP1.Core/Runtime/VM/LevelSurfLightmap.cs`](../HP1.Core/Runtime/VM/LevelSurfLightmap.cs) (the rule), [`HP1.Core/Runtime/World/UELevelRuntime.SurfLightmaps.cs`](../HP1.Core/Runtime/World/UELevelRuntime.SurfLightmaps.cs) (world binding; zone ambient comes from the zone actor's AmbientBrightness, Hue and Saturation, or from LevelInfo when a zone has no actor). A lightmap tile exists per (lightmap, zone) pair, because the cache keys contain the zone byte.
- Open (stated in the source): cache 0x18 is not rebuilt for `bLightChanged` (bit 0x1000 at +0x28 is only written under the editor in the decompile; the absence of other writes is not confirmed from disassembly); caches 0x15 and 0x16 are not kept, so a category-1 light of flag 0 whose inputs change after the first frame would keep its old filler in the original but is recomputed in the port (the port reports that case rather than hiding it); at most 256 records (a larger count is a refusal); memory-cache eviction is not modelled.

## Mover lightmaps and mode 3

- A mover surface (`FMovingBrushTracker::SurfIsDynamic`) takes one of two branches. A mover without `bDynamicLightMover` uses the level branch over its own brush model (Brush +0x168): its `iLightActors`, then the +0x48 list of its tracker surface. Port: [`HP1.Core/Runtime/World/UELevelRuntime.MoverLightmaps.cs`](../HP1.Core/Runtime/World/UELevelRuntime.MoverLightmaps.cs).
- A mover with `bDynamicLightMover` (+0x2d0 bit 0x10) is mode 3 (0x10b07a52..0x10b07b4f). The editor bakes nothing for it; the lights are taken from the BSP leaf the mover stands in now (`Model->Leaves[Region.iLeaf].iPermeating` into `Model->Lights`, in pool order), for each face in its current pose, with the face plane side test `0.0 < (L - Origin).Z`. The light's `bSpecialLit` must equal the mover's own. Category-0 records are merged first, then 1 and 2, list order inside each. The fill uses no shadow mask (0x7f). Dynamic lights from the +0x48 list pass the same bSpecialLit check, the mover itself is rejected, the rest are category 2. With no leaf (`Region.iLeaf == -1`) or `Leaves.Num == 0` the whole branch is skipped and only the ambient seed remains.
- The +0x40 volumetric list in this branch only marks records and adds category-3 records; neither reaches the lightmap.
- A mover is recomputed only when its pose, leaf, zone, leaf lights or a light's per-frame effect change. A mover lightmap is seeded from the zone of the node its fragment is drawn through (0x10b079d7, cache key lightmap plus zone byte). Open: a lightmap whose fragments lie in zones of different ambient keeps its current tile; a per-fragment piece is not built.
- Port: [`HP1.Core/Runtime/VM/MoverMode3.cs`](../HP1.Core/Runtime/VM/MoverMode3.cs) (selection and categoriser), [`HP1.Core/Runtime/VM/MoverMode3Lightmaps.cs`](../HP1.Core/Runtime/VM/MoverMode3Lightmaps.cs) (wiring over mover geometry).

## Dynamic lights reaching surfaces

- `URender::SetupDynamics` admits a light only if LightType, LightBrightness and LightRadius are non-zero and it is not (bStatic|bNoDelete) without `bDynamicLight`; the occlusion walk then filters it down the tree into `SurfLights` and `LeafLights` (see `frame-tree-and-occlusion.md`). The light's radius is `WorldLightRadius`, raised to `(VolumeRadius + 1) * 25` when that is larger.

## Actor lighting (`SetupForActor`)

- Sources: the level ambient from `Actors(0)` and every light with LightType non-zero and LightBrightness above 0. Per actor: the BSP leaf sublist (`iPermeating`) plus the dispatched dynamics of the actor's leaf (`UESprite.LeafLights`), paired by `bSpecialLit`, distance within the radius, score `ROUND((1 - d/R) * Brightness * 1024)`, sorted descending (UE1 `Sort`, `FUN_10b0d030`; equal scores keep that sort's order), threshold score/8 after the first accepted, cap 3+3 lights, line of sight from light to actor Location against the BSP only (`Model->LineCheck`, TRACE_Level). When no fresh trace is done, the pair counter bit decides, on the schedule `(Index ^ frame) & 0xf`.
- Fade: each (source, actor) pair keeps a counter in an `FMemCache` item (up to 16 pairs). The rate is `ROUND(dt * 768)` clamped to 0..255, with dt the viewport's wall-clock frame time (0x10b09bd2..0x10b09c03: not paused, no TimeDilation). Accepted lights gain `rate | 1`, rejected ones lose `rate`; the exported colour is multiplied by `counter / 255`; up to 16 entries are exported.
- Gates: `bUnlit` actors and actors in leaf -1 get no list (0x10b09b79, 0x10b09b86). The export array holds 256 records of 0xc4 bytes, with no count check on the accept path.
- One call per `DrawMesh`: an actor drawn by k frames of the tree advances its counters k times in a tick, and each frame draws with its own call's list. A third-person weapon is drawn with its pawn's sprite and takes the pawn's lists.
- Port: [`HP1.Core/Runtime/Render/UEActorLighting.cs`](../HP1.Core/Runtime/Render/UEActorLighting.cs), [`HP1.Core/Runtime/Render/UEActorLights.cs`](../HP1.Core/Runtime/Render/UEActorLights.cs) (run once per tick after `DrawWorld`; the frontend reads the results and runs the per-vertex body).

## Coronas

- The corona block sits at the tail of every `DrawFrame` (Render.dll 0x10b26742..0x10b26e0f) with a helper `FUN_10b26f10` (0x10b26f10..0x10b27045). Gate: the viewer's `Region.iLeaf != -1`, a zone, `RenDev->Coronas` (+0x60), and `Frame->Recursion == 0`, so only the master frame draws coronas.
- Candidates are the static lights of the viewer's leaf (`Model->Leaves[iLeaf].iPermeating` into `Model->Lights`), then `URender::LeafLights[iLeaf]`. In 1.53 the dynamic list is already empty at this point (`OccludeFrame` clears it right after `OccludeBsp`, 0x10b25472..0x10b2548f), so the port has no dynamic candidate pass. The candidate rule has no distance test: only leaf membership plus the line check cut a distant lamp off.
- A candidate needs `bCorona` (+0x1f0 bit 4), a `Skin`, not `bDeleteMe`, and `XLevel->SingleLineCheck` from the camera origin to the lamp's Location, TraceFlags 6 (Level plus Movers), zero extent, finding nothing. Pawns are not in those flags, so Harry and other characters standing between the camera and a lamp do not hide its corona; the corona is drawn as a screen tile with no depth test. Decorations such as statues and armour do not block it either.
- A table of 32 slots (an `FMemCache` item, 0x180 bytes) holds {actor, actor index, brightness}. Each run, every used slot decays by `dec` and a slot below 0 is freed. A lamp already in a slot gains `dec + dec` (capped at 1); a new lamp takes the first free slot with `min(dec + dec, 1)`; if none is free it is dropped. `dec = float(float(now - prev) * 2^-32 * 3)`.
- Drawing: `UCanvas::DrawIcon` (vtable +0x64) of the Skin at screen centre minus half size, size `Frame->X * DrawScale * 0.8`, PolyFlags 0x104, colour from a hue/saturation conversion of LightHue and LightSaturation (constants 1/85 and 1/84) times brightness. Everything is computed in the 24-bit x87 window.
- Port: [`HP1.Core/Runtime/Render/UECoronas.cs`](../HP1.Core/Runtime/Render/UECoronas.cs); the trace and the pawn test are in [`HP1.Core/Runtime/World/UELevelRuntime.cs`](../HP1.Core/Runtime/World/UELevelRuntime.cs), the wiring in [`HP1.Core/Runtime/VM/UEWorldFrameProducer.Views.cs`](../HP1.Core/Runtime/VM/UEWorldFrameProducer.Views.cs).
- Not original (improvement, author 2026-11-03): the fade clock is Core's viewport clock (the sum of the engine frame deltas Core receives); the original reads wall time (`appSeconds`/rdtsc FTime) at each run of the block. The original's table can also be flushed with its memory cache; the port keeps it for the process lifetime. Open: the author's remark that coronas should glow at any distance is not reproduced; the port has the same leaf cut-off as the original (one Lev_Tut1 lamp pair: visible at 60..150 units, absent from 300). It needs a map and place from the author or a live capture of the original.
- Not original (improvement, author 2026-11-08, Enhanced visual mode only): the corona ray also fails when the collision cylinder of a visible, drawn, opaque pawn is crossed, so Harry and other pawns hide a corona behind them, and the original fade (+2*dec up, -dec down) makes it fade smoothly. A pawn whose cylinder holds the ray start never blocks; a see-through pawn (Opacity below 1, such as Harry under the cloak; `STY_Translucent` ghosts; `STY_Modulated`) and an undrawn one (DrawType None, for example the tentacula's head) never block. Only pawns block. In Original mode (`VisualMode=Original`) only TraceFlags 6 is used, as in the retail game. Port: `CoronaPawnClear` in [`HP1.Core/Runtime/World/UELevelRuntime.cs`](../HP1.Core/Runtime/World/UELevelRuntime.cs).
